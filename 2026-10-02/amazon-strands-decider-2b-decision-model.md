## 摘要

- AWS 推出開源決策模型 Strands Decider 2B，靈感來自 TypeSafe 的 Jev；它能從預先定義的選項中快速選擇，並提供信心分數。
- 這個模型由 Qwen3.5-2B 的基礎架構改造而來，不生成任意文字，體積小到可以在本機執行。
- AWS 傑出工程師 Marc Brooker 因客戶代理工作流程的需求著手開發；這類任務未必需要大型語言模型每次都動用完整能力。
- 類似決策模型近期快速增加，顯示市場開始探索更適合自動化的低成本智慧，但模型準確度、校準與通用能力仍需取得平衡。
- TypeSafe 執行長 Diogo Almeida 認為，打造真正有用的模型並不容易；目前不少嘗試仍偏向驗證新架構，而非讓智慧在實際場景中發揮價值。
- Strands Decider 2B 已開源，適用於模型路由、工具選擇、評估、防護與記憶管理等代理系統環節。

Amazon Web Services（AWS）推出一款受 TypeSafe「Jev」啟發的開源決策模型。隨著 AI 開發者愈來愈想要適用於電腦自動化的智慧，而非每項工作都依賴前沿大型語言模型（LLM），這類模型開始受到關注。

Amazon 的 Strands Decider 2B 與 OpenAI 在同一週宣布的類似產品相近，能以高速、低成本在預先定義的選項間做選擇，並回報對選擇的信心程度。這款模型已完整開源，現在即可使用，而且小到能在本機執行。

Amazon 傑出工程師 Marc Brooker 在接觸 Jev 後，開始嘗試打造自己的同類模型。他自行開發的版本表現不錯，一度登上同尺寸模型 Jevbench 排行榜第一；之後 Amazon 工程師將專案整理完善，並以 Strands Labs 的名義發布。Strands Labs 致力於開發部署 AI 代理的新工具與協定。

Brooker 表示，這個工具的需求來自他與 AWS 客戶的交流：客戶的代理工作流程並非每個環節都需要完整 LLM 的能力或成本。

「最初讓我對這類模型感興趣的，是它們很適合擔任工作流程中的決策者：『根據我目前所處的狀態，下一步該做什麼？』」Brooker 告訴 TechCrunch。他表示，這讓客戶能在工作流程中採用一種更可靠的步驟：答案範圍封閉，還有信心分數可參考，同時可能具備更低延遲與更低成本。

和其他決策模型一樣，Strands Decider 建立在 LLM 的「軀幹」之上，此處使用的是 Qwen3.5-2B；但它不生成文字，而是輸出經過校準的選擇。TypeSafe 以經濟學家威廉・史丹利・傑文斯（William Stanley Jevons）為 Jev 命名，呼應他的理論：某種事物的成本下降——例如電腦智慧——反而可能推升需求。

自 TypeSafe 推出這個概念後，研究者已打造出數十種類似模型。這顯示各界興趣廣泛，但也引出它們究竟能有多大價值的問題。Brooker 認為，挑戰在於提升模型快速決策的表現，同時不犧牲智慧能力。

「要拿捏一個非常微妙的平衡：你希望提升模型在這些任務上的準確度與校準品質，同時又不能削弱它理解不同語言、保有知識的能力；正是這些通用能力，讓它有趣、實用且具有廣泛用途。」他告訴 TechCrunch。

儘管如此，Brooker 不認為前沿 AI 實驗室必然會主導這個領域，尤其是規模較小的市場，打造出有意思的產品可能只需數百或數千美元。

TypeSafe 的主管則表示，他們目前仍專注於改進後續模型。

「我知道大家覺得這像一場淘金熱，但他們可能低估了要讓模型真正聰明有多難。」TypeSafe 執行長暨創辦人 Diogo Almeida 告訴 TechCrunch。他表示，目前還看不到真正的競爭者正在崛起。

他補充：「現在這批產品看起來比較像是機器學習研究者想實作一種很酷的架構，而不是一支專注於讓智慧真正派上用場的團隊。」

## 從生成模型到選擇模型：代理系統開始拆分工作

代理執行流程中的許多步驟，其實不是開放式寫作或複雜推理，而是分類、挑工具、判斷是否升級處理。若這些環節都交給大型生成模型，不只可能增加延遲與費用，也讓系統必須額外處理格式控制和信心判斷。決策模型把輸出空間縮小，換取更直接、可衡量的選擇。

這不代表小模型能取代前沿模型。更合理的方向是分工：由決策模型處理範圍明確、重複性高的選擇，把真正需要廣泛知識或多步推理的問題交給大型模型。真正的關鍵仍是準確度與校準是否可靠；如果信心分數不能支援適當的升級機制，較低成本未必能換來更安全的代理工作流。
